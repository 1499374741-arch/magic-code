# Magic Code MVP 范围与里程碑

## 首版目标

用最短闭环验证 Magic Code 的核心假设：相比用文字描述，直接指向生成内容中的目标，能否让 AI 更准确地完成局部修改，并减少用户重复解释。

首版优先覆盖网页/HTML 预览和聊天文字追问。它不是完整的设计编辑器，也不承诺首版支持所有 AI 平台和文件格式。

## MVP 范围

### 必须交付

- 主聊天与侧边预览并存；预览绑定当前会话。
- 支持 AI 生成的 HTML/网页内容安全预览，并保留原始输出。
- 点选页面元素，生成包含元素语义和邻近上下文的修改请求。
- 选中聊天文字，在独立小窗内追问；小窗与主聊天状态隔离。
- 基础文本批注；批注可检查、编辑、删除，并能复制或发送给 AI。
- 明确的空、加载中、错误、定位失败和内容过期状态。

### 暂不纳入

- 语音输入、区域圈选和多人协同。
- 完整的多小窗标签管理。
- 多格式导出和专业级元素属性面板。
- 复杂版本分支、合并、自动比较。

## 建议迭代阶段

| 阶段 | 交付重点 | 退出条件 |
|---|---|---|
| 0. 技术验证 | 确定宿主形态；验证 HTML 沙箱预览、元素命中、会话绑定和 AI 上下文传递 | 至少一个端到端原型可将点选元素准确传给模型；确认跨域和安全边界 |
| 1. 交互原型 | 打通聊天、预览、定点模式和独立追问的主要界面与状态 | 代表性用户能无需讲解完成两条核心流程；严重误触和迷失问题清零 |
| 2. MVP 实现 | 实现首版必须交付的功能，加入批注和错误恢复 | 验收标准全部通过；预览失败不影响原始内容与主聊天 |
| 3. 小规模内测 | 收集定位正确率、重复解释率、预览可靠性和用户反馈 | 找到主要失败模式；核心指标达到团队设定门槛后决定扩大测试 |
| 4. 首轮迭代 | 基于数据完善稳定定位、批注同步或版本回退中的高价值项 | 优先解决高频失败；再评估语音、圈选、协作等扩展 |

## 发布门槛

- 定点请求携带可读的元素语义上下文，不依赖裸坐标。
- 用户可在发送前核对目标，且可安全退出定点模式。
- 独立追问不改变主聊天的消息序列、输入内容和会话焦点。
- AI 预览在沙箱中运行；脚本错误、超时或内容不兼容时可回退查看原始输出。
- 关键状态、键盘操作和小屏幕布局完成基本可用性检查。
- 明确说明发送给模型的上下文范围及数据保留/删除方式。

## 内测方案建议

邀请 5–8 位经常使用 AI 做网页或文案修改的用户，给每人相同任务：一项定点修改、一项选中文字追问、一项批注反馈。观察而非只询问：

- 用户是否能自然找到并理解定点模式。
- AI 是否识别了用户实际指向的对象。
- 用户是否需要再次描述目标，或手动修正定位。
- 小窗是否真的降低了主线干扰。
- 哪种预览内容最有价值、哪些失败会阻断使用。

测试开始前为上述指标定义记录方式和团队通过门槛；首轮测试用于建立基线。

## 关键依赖与风险

- 目标宿主平台必须允许读取消息选区并展示侧边内容，或提供可行的扩展/插件接口。
- 生成内容的预览方案需支持隔离运行，不能为了方便而把不可信 HTML 放入主页面执行。
- DOM 语义定位受动态渲染和跨域 iframe 限制；失败时需要区域截图/坐标说明等有提示的降级路径。
- 调用模型需能把预览目标和小窗引用作为额外上下文传递；不同模型供应商的接口能力需确认。

## MVP 后的优先级建议

1. **批注一键同步**：缩短“在页面发现问题”到“AI 收到完整反馈”的距离。
2. **历史版本回退**：降低用户尝试局部修改的心理成本。
3. **圈选区域与快捷指令**：提高多元素、重复操作的效率。
4. **多小窗管理**：当内测显示用户确实会并行保留多个问题时再加入。
5. **语音、导出、属性提示、多人协作**：依据目标人群和使用数据分别评估，不预设为必需能力。
